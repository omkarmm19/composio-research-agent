## 🚀 How to Run

### Prerequisites

1. **Python 3.8+**
2. **Gemini API key** (free): Get one at [aistudio.google.com/apikey](https://aistudio.google.com/apikey)
3. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

### Environment Variables

```bash
export GEMINI_API_KEY="your-key-here"
```

### Step 1 — Run the Research Agent
```bash
python agent.py
```
- Researches all 100 apps sequentially using Gemini Flash 2.0 with Google Search grounding
- Saves results to `data/research_output.json` after each app (crash-safe)
- Resume-capable: if interrupted, re-run and it picks up where it left off
- Rate-limited to 5s between calls (respects Gemini free tier: 15 req/min)
- ~9 minutes total at 5s/app

### Step 2 — Run the Verifier
```bash
python verifier.py
```
- Samples 20 apps across all 10 categories
- Re-verifies 5 fields per app against real documentation
- Applies corrections back to the dataset
- Outputs `data/verified_output.json` and `data/verification_log.json`
- Shows accuracy improvement from Pass 1 → Pass 2

### Step 3 — Run the Analyzer
```bash
python analyzer.py
```
- Generates pattern analysis and key insights from verified data
- Outputs `data/analysis.json`
- Prints key findings to stdout

### Step 4 — View the Deliverable
Open `index.html` in any browser. All data is embedded — no server needed.

```bash
open index.html  # macOS
```

## 🤖 How the Research Agent Works

### Architecture

```
apps.json (100 apps)
    ↓
agent.py
    ├── For each app: build structured prompt
    ├── Call Gemini Flash 2.0 with Google Search tool
    ├── Extract JSON with 12 fields
    ├── Save after each app (crash recovery)
    └── Sleep 5s (rate limit)
    ↓
data/research_output.json
    ↓
verifier.py (20 sampled apps)
    ├── Re-verify 5 fields per app
    ├── Record hits/misses/corrections
    └── Apply corrections to dataset
    ↓
data/verified_output.json + verification_log.json
    ↓
analyzer.py
    ├── Auth method distribution
    ├── Category buildability breakdown
    ├── Easy wins vs. outreach lists
    └── Key product insights
    ↓
data/analysis.json → embedded in index.html
```

### Fields Extracted Per App

| Field | Description |
|-------|-------------|
| `name` | App name |
| `category` | One of 10 research categories |
| `what_it_does` | One-line description |
| `auth_methods` | OAuth2 / API key / Basic Auth / Bearer / Bot token / other |
| `access_model` | Self-serve Free / Trial / Paid / Enterprise / Partner Gated |
| `access_notes` | How to actually get credentials |
| `api_type` | REST / GraphQL / WebSocket / CLI only / No Public API |
| `api_breadth` | Comprehensive / Moderate / Limited / None |
| `mcp_exists` | Boolean — does an official MCP server exist? |
| `mcp_notes` | MCP server details or explanation |
| `buildable_today` | Yes / Partial / No |
| `main_blocker` | Primary obstacle if not fully buildable |
| `evidence_url` | Primary documentation URL |
| `confidence` | High / Medium / Low |

## ✅ Verification Methodology

**Sample**: 20 apps across all 10 categories (2 per category)  
**Fields checked**: auth_methods, access_model, api_type, mcp_exists, buildable_today  
**Method**: Second Gemini agent with stricter verification prompt + human review  

| Pass | Accuracy |
|------|----------|
| Pass 1 (agent only) | ~71% |
| Pass 2 (post-verification) | ~94% |

**4 corrections applied**:
- Google Ads: Developer Token approval step missed → buildability corrected to "Partial"
- Plaid: Production approval process missed → buildability corrected to "Partial"
- HubSpot: Official MCP server missed in first pass → mcp_exists corrected to true
- WhatsApp Business: System User Token auth method missed → auth_methods corrected

**7 human interventions** documented for ambiguous/gated apps (Fanbasis, iPayX, Pylon, Consensus, Paygent, Sherlock, Mermaid CLI).

## 📊 Key Findings

- **72/100** apps buildable as Composio toolkits today
- **57 easy wins** (self-serve + fully buildable)
- **68%** of apps use OAuth2 (dominant auth pattern)
- **18 apps** already have official MCP servers
- **5 apps** have no public API (fundamental blockers)
- **Productivity/Dev/Infra/Comms** = easiest categories (8-10/10 buildable each)
- **Finance/AI** = hardest (5/10 and 4/10 easy wins respectively)
